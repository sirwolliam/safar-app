## 0. How to use this document (read first)

- **This TDD describes what IS, not what's planned.** When code and this doc disagree, the code wins — then fix this doc.
- **File drift is the recurring hazard.** Project-knowledge file copies are presumed stale. Before touching, referencing, or editing any file, ask for it fresh. Never trust a Claude Code summary of what it did — always get the actual file back and read it before telling the user to test. **This stretch produced a real example**: a four-part find/replace prompt for `UmrahGuideScreen.jsx` silently applied zero of its four blocks — Claude Code reported nothing, the file just came back completely untouched. Always re-verify after "no errors" reports, especially multi-block prompts.
- **Before building anything, grep the code for the specific thing you're about to build** to confirm it doesn't already exist and to see its real state.
- Working directory for source is the project root; screens live in `screens/`.
- **Two separate "skills" systems exist and don't share access.** This claude.ai conversation only sees skills enabled via claude.ai's own Customize → Skills. The person's **Claude Code CLI has its own, separate local skill library** at `~/.claude/skills/`, confirmed to contain: `brandkit`, `emil-design-eng`, `extract-design-system`, `find-skills`, `image-to-code`, `ui-ux-pro-max`. This chat cannot read or use those — they're local files on the person's Mac, invisible to this environment. When a design reference/mockup needs translating into code, **route it through Claude Code with those skills named explicitly** (especially `image-to-code` and `extract-design-system`) rather than trying to eyeball it here — proven this stretch to produce meaningfully better output (the guide-screen dashboard redesign) than what was built freehand in-chat.

## 11. Pilgrimage Map — Rebuilt (Direction B: map-first)

*Fully rebuilt this stretch, in several iterations. This section replaces the "not yet built" status from the prior TDD.*

### 11.1 Direction chosen
Between two structural options proposed (A: cinematic photo-first like the old `GuideCarousel`, or B: map-dominant with photo/text as secondary), **B was chosen and built** — the map is the one thing that makes this screen distinct from Lesson Flow and the guide screens' own resource tiles, so it leads.

### 11.2 Current structure — `MapScreen.jsx`
Root is a plain `View` (not `SafeAreaView` — safe-area insets are applied manually so the header can bleed to the true top edge, a fix that had to be applied explicitly; `SafeAreaView` was blocking the bleed).

Top to bottom:
1. **Ornate header**, deliberately matched to `MyContactsScreen.jsx`'s exact pattern (`HeaderPatternBg`, `SAGE = "#4A5C48"` band, `CARD_BG = "#FDFAF4"` back-button chip and title color, 38px serif title). Title: "Umrah Map" / "Hajj Map" per `route.params.guide`. Subtitle (14px): **the current step's own name** ("Ihram," then "Entering Masjid al-Haram," etc.) — updates live as the person swipes or taps through steps.
2. **Stepper row** — arrows + pips, fixed below the header (not part of the scroll).
3. **Map image — true full width, true aspect ratio.** Each step's real image dimensions are read synchronously via `Image.resolveAssetSource()` and the container is sized to match exactly (`width: SW, height: SW * (realHeight/realWidth)`) — this was a real fix: the original `resizeMode="contain"` inside a fixed-ratio box left empty space for images that didn't match that ratio. Tapping the map opens a full-screen modal with pinch-zoom/pan (`ScrollView` with `minimumZoomScale`/`maximumZoomScale`, no external zoom library — RN's built-in support, to avoid adding a dependency that might need its own native rebuild).
4. **Site photo card** — landscape, own card, below the map.
5. **Step info card** — pill ("Step X of Y"), bigger title (24px) and description (16px, no more hard truncation now that the layout scrolls), optional note, and two real filled buttons: sage "Full Guide" (→ `LessonFlow` with the step's `lessonId`, only rendered when one exists) and outlined "Duas" (→ `PilgrimageDuas`) — replacing the original small inline text links.

Swipe (via `PanResponder`, same threshold/pattern as Sacred Places and Lesson Flow) attached to the whole `ScrollView`, not just the map layer.

**Toggle removed entirely** — `guide` comes from `route.params`, set by whichever guide screen navigated here. `PulsingDot` and the old `markerPos`-overlay approach are gone; the new locator images are self-contained infographics with the highlighted spot already baked in (same lesson already learned on Sacred Places).

### 11.3 Umrah step data (6/6, fully real)
All six steps have real content, condensed from the actual Umrah lesson PDFs (not freehand-written) into 2–3 sentence descriptions, each linked to its real Lesson via `lessonId`:

| # | id | Image | lessonId |
|---|---|---|---|
| 1 | ihram | `map_umrah_01_miqaat.png` | umrah-03 |
| 2 | enter | `map_umrah_02_entering_haram.png` | umrah-05 |
| 3 | tawaf | `map_umrah_03_tawaf.png` | umrah-06 |
| 4 | maqam | `map_umrah_04_maqam_zamzam.png` | umrah-07 |
| 5 | sai | `map_umrah_05_safa_marwah..png` | umrah-08 |
| 6 | halq | `map_umrah_06_halq_taqseer.png` | umrah-09 |

**Known filename typo, not yet cleaned up:** step 5's map image is `map_umrah_05_safa_marwah..png` — a genuine double-dot in the actual saved filename (confirmed against the person's own Finder listing), preserved in code so nothing breaks. Renaming the file to a single dot and updating the one `require()` line is a trivial pending cleanup.

The Umrah map images went through a real verification cycle before being trusted: the person's first "Kaaba & Miqaats" infographic had two of five Miqat directions wrong (Qarn al-Manazil shown Southwest, should be East; Dhat Irq shown West, should be Northeast) — caught by cross-referencing multiple independent sources including the Saudi Press Agency, corrected via a targeted regeneration prompt. A second gates diagram ("Entering Masjid al-Haram") also had unverifiable/wrong gate names and positions (King Abdulaziz shown North instead of confirmed West; Al-Fath shown South instead of confirmed North; "Ajyad Gate" and "Al-Shubaikah Gate" couldn't be verified as real named gates at all) — resolved by simplifying to generic "Entry Gate" labels rather than asserting specific, unverifiable gate identities. **Lesson for any future locator-map work: verify real spatial/directional claims against multiple independent sources before treating an AI-generated infographic as ground truth — this image-generation pipeline produced confirmed factual errors twice in one batch.**

### 11.4 Hajj step data — still on the placeholder
All 6 Hajj steps (`ihram`, `mina`, `arafat`, `muzdalifah`, `jamarat`, `ifadah`) still share `Umrah_map_test1.png` — the original misleading-placeholder problem this whole redesign was meant to fix, **not yet resolved for Hajj.** No `lessonId` fields set for Hajj steps either (so no "Full Guide" button renders for any Hajj step yet). This is the single largest open item from this stretch — see §14.

### 11.5 `MapStepListScreen.jsx` — new file, the list-first landing screen
Sits in front of `MapScreen`. Same ornate-header treatment as `MapScreen` (title = "Umrah Map"/"Hajj Map", subtitle = "{N} Steps, Start to Finish"). Below the header: an explainer card (no icon — removed per feedback; text bumped to 16px; a line break before a bolded final sentence: *"Tap any step below to explore it, or work through them one by one."*; opening line reads "These maps walk you through…" since it's describing the whole set, not one map). Then the step rows (thumbnail photo, "STEP N," title at 18px, short sub), each tapping into `MapScreen` at the matching `stepIndex`.

Both guide screens' "Pilgrimage Map" resource link now points here (`navigate("MapStepList", { guide })`), not directly into `MapScreen`.

## 12. Hajj/Umrah Guide Screens — Rebuilt as Dashboards

*New this stretch. Two major redesign passes: an in-chat "eyebrow" version (superseded, not documented further), then a substantially more sophisticated rebuild produced by routing the person's own design mockup through **Claude Code directly using its local `image-to-code` and `extract-design-system` skills** (see §0) — that version is what's live and described below.*

### 12.1 Why this replaced the "eyebrow" redesign
The in-chat version (atmospheric header, eyebrow section labels, a sage "Start Learning" card, compressed quick-access row, one atmospheric pause) was a real improvement over the original flat card-stack, but Claude Code's mockup-driven rebuild went further — a genuine dashboard with live state (countdown, checklist progress), tighter information density, and a resource grid — and the person judged it better. Worth remembering for future layout work on this app: **when a real design reference exists, get it into Claude Code with the right skills named rather than iterating blind in chat.**

### 12.2 Current structure — both `HajjGuideScreen.jsx` and `UmrahGuideScreen.jsx`
Shared shape (Hajj = sage accent, Umrah = gold accent):

1. **Hero** — headline + subhead on the left, a cropped photo on the right (no gradient fade — an earlier "faded gradient" treatment was explicitly removed per feedback in favor of a clean crop). Guide pill badge ("HAJJ GUIDE"/"UMRAH GUIDE"). Hajj's hero image: `hajj_guide_card.jpg` (same asset reused from the Learn Hub promoted card). Umrah's: `kaaba_mixed.png`. **A third filename, `guides_header.png`, was requested by the person but its scope (replace one hero, both, or something else) was never confirmed before this snapshot — unresolved, see §14.**
2. **Countdown card** — live H:M:S ticking timer (`setInterval`, 1s) computed from `safar_departure_date_v1`, with a Kaaba/tent illustration (`kaaba_framed.png` for both, after `SP_mina.png` was caught being misused at 68px — a Sacred Places infographic with baked-in labels illegible at that size — and swapped out). "Edit date" was originally a small top-right button; **moved to a full-width row at the bottom of the card** per feedback, alongside "Update your plans." Kaaba/tent image enlarged ~40% (68px → 95px) per feedback.
3. **"Your journey" step path** — a decorative, non-interactive row of stage labels with dots and connecting lines. **Umrah**: one row, 5 stages (Prepare/Ihram/Tawaf/Sa'i/Complete). **Hajj**: two rows of 4 (Prepare/Ihram/Mina/Arafah, then reversed per feedback so "Complete" sits far-left: Complete/Tawaf & Sa'i/Jamarat/Muzdalifah), connected by a curved SVG `Path` (`react-native-svg`, already a project dependency) linking Arafah (top row, right end) down into Muzdalifah (bottom row, right end after the reversal) — replacing an initial straight-line connector that didn't match the person's sketch. **This step path is a fourth, independent representation of "the stages of pilgrimage,"** with counts/granularity matching neither Lesson Flow (16/10) nor Map (6/6) — flagged as a known, deliberate-for-now inconsistency since it's purely decorative (no taps, no shared data source). Not resolved.
4. **"Start your learning path" card** → `LessonList`. Tinted a light background color matching each guide's accent (`SAGE + "12"` / `GOLD + "14"`, i.e. roughly 7–8% opacity) — subtle, not high-contrast, per explicit instruction. **Hajj's tint was originally sage, then changed to gold** to match Umrah's for cross-screen consistency, per feedback — both guide screens' Start Learning and Quiz cards now use the gold tint regardless of the sage/gold accent used elsewhere on each screen.
5. **"Along the way" resource grid** — 6 compact tiles (3×2): Duas, Videos & Media, Essentials (Shop), Pilgrimage Map (→ `MapStepList`), Sacred Places, and a Checklist tile showing live progress (`"{doneCount} of {TOTAL} tasks completed"` + a thin progress bar) that navigates to the Plan tab rather than rendering an inline checklist here. **Whether the actual interactive tap-to-check-off checklist UI still exists somewhere in the Plan tab was never confirmed — open item, see §14.** Tile secondary text bumped 11px → 12px per feedback.
6. **"How ready are you?" quiz card** → Practice tab. Same tint treatment as the Start Learning card.
7. **Verse card** — full-bleed photo + gradient scrim, real Arabic + translation + citation. Hajj: Al-Baqarah 2:197 ("Hajj is [in] well-known months…"). Umrah: Al-Baqarah 2:196 ("And complete the Hajj and Umrah for Allah."). Both citations checked against the actual verse content, not just plausible-sounding — correct.

### 12.3 Real bug fixed this stretch, worth remembering the pattern
`tripDate` (used for the countdown) is fetched once on mount (`useEffect` with `[]` deps) — **it does not re-fetch on screen focus**, unlike `doneCount` (checklist progress) which correctly uses `useFocusEffect`. This means editing the departure date via the shared `TripDetailsEditor` (from Home or Settings) and returning to a guide screen will show a stale countdown until the app is force-restarted. **Not yet fixed** — flagged, not actioned. Given `TripDetailsEditor` was built specifically to be one shared source of truth across the app (§9 in the prior TDD), this screen not participating in that pattern is a real gap.

## 13. Learn Hub — Guide Cards Promoted

*New this stretch, in `LearnMainScreen.jsx` (the actual filename — "LearnHubScreen" doesn't exist; this was a naming mix-up caught before any code was written).*

Umrah Guide and Hajj Guide were two of six uniform rows in a flat list (same visual weight as "Islamic References"). Split into a separate `GUIDES` array, rendered as two large (190px) full-bleed photo cards above the remaining four rows — reusing the same hero-card visual language already established on the guide screens themselves, rather than inventing a new pattern. Each card shows title, a short evocative subtitle (deliberately **not** a feature-list sentence — see reasoning below), and a row of small tag pills ("Guide · Duas · Map · Checklist") hinting at scope without turning the card into a paragraph.

**Explicit design reasoning, worth preserving:** the person asked whether the card description should list everything the guide contains (step-by-step, duas, media, maps, checklist). Pushed back — a card's job at this level is to make someone want to tap in, not pre-inventory itself; the guide screen already shows all of that the instant someone arrives, so restating it outside is redundant and less scannable than the real thing. The tag-pill row was built as the lighter-weight alternative, and the person accepted that direction.

Card images: `umrah_guide_card.png`, `hajj_guide_card.jpg` (per-guide, swapped in after the initial build used `ihram.jpg`/`tawaf2.jpg` placeholders).
